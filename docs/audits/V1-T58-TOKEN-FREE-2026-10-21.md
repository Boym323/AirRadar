# Token-free public T58 monitoring — V1

**Status:** implementation candidate; production soak and database rollback are NOT VERIFIED. This does not authorize deployment or repository archival.

## Behavior and security

- `T57_PUBLIC_ONLY=1` activates explicit, token-free, read-only sampling of existing `/api/system/status` and `/api/system/runtime-performance`.
- The default T57 admin sampling mode remains unchanged. Public T58 never fetches `/api/watchlist/session`, supplies session cookies, or requires `T58_WATCHLIST_ADMIN_TOKEN`.
- Public sampling is intentionally limited to CPU interval, RSS/heap, event-loop windows, public build identity, and basic health. It does **not** measure private retention, exact process identity, major-GC, SQL cache, event attribution, or Digital Twin forensics.
- Administrative writes and privileged reads remain protected by signed sessions; disabling their authentication on an internet-facing service would be unsafe.
- The bounded private journal still has restrictive permissions. Public and admin journals are explicitly incompatible on resume. Report validation rejects secret and aircraft-identity keys.
- One-hour sampling still uses seven read-only chunks and rejects insufficient coverage, identity change, missing windows, or unavailable API data. A successful public result is only `PASS_WITH_LIMITATIONS`, not an admin-forensics or production rollback PASS.
