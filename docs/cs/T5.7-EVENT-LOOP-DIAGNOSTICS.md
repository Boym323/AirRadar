# T5.7B atribuce event loopu a CPU

Existující procesně sdílený `runtime-health-observation` zůstává jediným
pozorovatelem event loopu. Nyní ukládá bounded minutová okna p95/p99/max (15
oken) a resetuje pouze ze sdíleného timeru observeru, takže čtení routy měření
nedeformuje.

`runtime-performance` zachovává kumulativní bounded ring a přidává 15minutový
časový horizont pro každou operaci. Každá operace uvádí wall time, přibližný
procesní CPU čas a zbytkový wait time. U synchronních operací je CPU měřený
wall interval; u asynchronních operací vychází z `process.cpuUsage()`. Při
překryvu async operací jde o atribuci, nikoli profiler.

Nově lze rozlišit source merge, aktualizaci trailů, serializaci snapshotu,
Track Fusion, Operational Twin, history/DB transaction, enrichment a SSE
notify. Chování radaru se nemění.

Historické event-loop p99 T5.6 (~1,29 s) nelze přímo porovnávat s novým
minutovým oknem bez společného měřicího intervalu.
