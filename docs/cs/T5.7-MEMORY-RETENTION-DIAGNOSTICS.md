# T5.7A diagnostika retence paměti

Tato stránka zaznamenává omezenou diagnostiku přidanou po auditu T5.6. Je
procesně lokální a záměrně nesbírá V8 heap snapshot, graf objektů, retainery,
payloady, souřadnice ani chyby providerů.

## Vlastnictví a maximální životnost

Diagnostika pokrývá lokální a síťové mapy letadel, věk a počet trail bodů,
stávající limity Track Fusion a Operational Twin, bounded metadata/enrichment
cache, SSE snapshot cache a pomocné mapy `AircraftStateService`. Je dostupná v
`runtime.diagnostics.retentionAttribution` v existující admin diagnostice.

Hodnoty popisují členství v bounded kontejnerech a jejich věk, nikoli počet V8
bajtů. `staleRetained > 0` je signál k následné kontrole, nikoli důkaz leaku,
protože může být legitimním výsledkem source-affinity grace cesty.

## Interpretace baseline a následné měření

Dodané hodnoty T5.6 prokazují velký pracovní set a retenci alokátoru, ale samy
neidentifikují retainer. Audit aktuálního kódu nalezl bounded vlastníky, nikoli
neomezený kontejner. Diagnostiku je třeba sbírat spolu s 60s runtime telemetry
nejméně 24 hodin a porovnat ji s RSS, heap-used, old-space po major GC, počtem
letadel, SSE klientů a velikostmi cache. Teprve monotónní růst mapy po návratu
provozu k baseline, přežívající přes více major GC, je kandidát na leak.
