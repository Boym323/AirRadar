# T5.7C – 24hodinový read-only produkční audit

## Účel a předpoklady

T5.7A a T5.7B doplnily procesní diagnostiku retence, minutová okna
event loopu a CPU/wait atribuci jednotlivých operací. Starší sampler
T5.6 nestačí pro 24hodinové měření ani pro všechna nová data. Tento
nástroj provádí pouze autentizované čtení. Před spuštěním ověř, že
produkční aplikace obsahuje PR #700 a #701 a že release je zdravý.

WATCHLIST_ADMIN_TOKEN musí být již bezpečně dostupný v chráněném
prostředí. Nezadávej token do historie shellu, PR, logů ani reportu.

~~~bash
cd /var/www/airradar
T57_SECONDS=86400 T57_INTERVAL_SECONDS=60 T57_WARMUP_SECONDS=600 \
  T57_EXPECTED_COMMIT=7564d8b \
  node scripts/t57-production-soak.mjs
~~~

Volitelný prefix očekávaného commitu musí odpovídat nasazenému
aplikačnímu commitu, nikoli pozdějšímu metadata-only commitu v GitHubu.
Použij samostatnou perzistentní terminálovou nebo servisní relaci,
aby odpojení SSH nepřerušilo 24hodinový audit. V produkčním checkoutu
nespouštěj build.

## Sběr a analýza

Skript standardně jednou za 60 sekund čte existující autorizované
administrátorské endpointy /api/system/status a
/api/system/runtime-performance. Povoluje pouze oficiální HTTPS hostitele
AirRadaru nebo loopback HTTP. Watchlist relace platí osm hodin;
sampler ji obnovuje po šesti hodinách a po výpadku čtení při dalším pokusu.

Průběžný NDJSON deník (výchozí umístění /tmp/airradar-t57-UTCčas.ndjson)
vzniká nově s oprávněním 0600. Umístění lze zadat přes T57_OUTPUT.
Každý řádek obsahuje pouze vybrané agregátní metriky; neobsahuje raw
HTTP odpovědi, token, cookies, ID interní diagnostiky, PID, identifikátory
ani souřadnice letadel nebo SQL. Dokončená minutová okna event loopu
a hot paths se ukládají bez opakování. Chybějící vzorky se evidují.

Při změně PID, identity diagnostiky nebo aplikačního commitu se založí
nový číselný segment. Výsledky různých procesů se nevyhodnotí jako
jediné nepřerušené období. Při předčasném ukončení zůstane NDJSON
soubor k analýze:

~~~bash
node scripts/t57-production-soak.mjs --analyze /tmp/airradar-t57-example.ndjson
~~~

Analyzátor vytvoří soukromé soubory .summary.json a .summary.md vedle
deníku; existující souhrny záměrně nepřepisuje.

## Interpretace reportu

| Verdikt | Podmínky |
| --- | --- |
| PASS_WITH_LIMITATIONS | Alespoň 95 % vzorků, dostatečná délka, jediný proces a build, minimálně 30 steady-state vzorků, dvě rozdílná major GC pozorování, deset dokončených oken event loopu a žádné překročení trail limitů |
| INSUFFICIENT_EVIDENCE | Nedokončená doba, nový proces, výpadky vzorkování, chybějící GC nebo event-loop měření |
| FAIL | Naměřené překročení retenčního limitu lokálních či síťových trailů |

Report zahrnuje percentily RSS, HeapUsed a Old Space, orientační
post-major-GC trend, minutové p99/max event loopu, intervalové CPU,
retenci kontejnerů a přibližnou CPU/wait atribuci. Rozdíl mezi první
a poslední desetinou steady-state vzorků je pouze pozorování,
nikoliv důkaz memory leaku. Je nutné zohlednit počet letadel,
zahřívání cache, typ provozu i počet skutečných SSE klientů.
Překrývající se asynchronní operace nelze považovat za přesný
výhradní CPU profil jednotlivých funkcí.

Nástroj nepřidává nové API, zápisy do DB, změny release pipeline,
restart služby, vynucený GC, produkční inspector, heap snapshot
ani syntetický SSE provoz. Merge PR samo měření NESPUSŤÍ;
po dokončení release jej musí spustit oprávněný provozovatel.
